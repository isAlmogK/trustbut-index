# Measure trustbut 0.7.0: families, success bar, pin

**Status:** Approved (2026-10-17)

**Feature:** [proof-first receipt spec](https://github.com/isAlmogK/trustbut/blob/main/docs/superpowers/specs/2026-10-17-proof-first-receipt-design.md) in trustbut. This spec covers the trustbut-index part only.

## Why

Labels of the 0.6.0 pilot (`labels/pilot-2026-10-17`, 71 findings) gave precision 5/71 = 7% and factual accuracy 62/71 = 87%. Every real finding said that nothing in the PR proves the change. trustbut 0.7.0 makes that its headline finding (`change-not-proven`), stops emitting `test-passes-without-change` and `no-tests-changed`, and fixes the three causes of the 9 false findings.

The success bar changes with it, decided after the pilot and disclosed as such: the study's pass bar becomes **factual accuracy** (are the facts trustbut states true) and **run coverage**. Precision (are they worth a reviewer's time) and the hit rate are still measured and published, without a pass bar.

## Changes

### 1. Families for `change-not-proven`

`change-not-proven` is counted in an existing family, chosen from the receipt:

- `untested-change` when the receipt has no `proofs` (no test changed, or no new or changed test that ran was found);
- `proof-gap` when it has proofs (new or changed tests ran and none fails without the change).

`countedFindings(r)` resolves this per receipt; `FAMILY_OF` keeps the plain id mapping for the other ids. The 0.6.0 ids stay mapped, so older pilot receipts aggregate as before.

### 2. One trustbut generation per results folder

`aggregate` fails with an error naming both versions when a results folder holds receipts from trustbut below 0.7.0 and from 0.7.0 or later: the proof families mean different things across that line. The pilot reruns into a new folder, so no folder mixes them.

### 3. Success bar

`THRESHOLDS` becomes `{ accuracy: 0.95, coverage: 0.5 }`. The verdict has `accuracy` (Wilson interval of (real + benign) / (real + benign + false) over all labeled findings) and `coverage` checks, and `pass` = both pass. `precision` and `hitRate` stay in the verdict as reported values with `target: null` and no `pass`. The report page shows four tiles: Factual accuracy and Run coverage with their bars, Precision and Hit rate marked "reported, no bar". It also shows a line for **"Nothing proves the change" worth a reviewer's time**: precision over labeled `change-not-proven` findings (by `finding.id`), with its interval.

### 4. Label prompt v2

`labels/prompt-v2.md` = v1 plus how to read `change-not-proven`: "Is the stated fact true (no new or changed test fails without the change, or no test changed)? Real if a reviewer of this PR would want a test that proves the change; benign for refactors, type-only, formatting, docs-strings, config, demo code, or changes a test cannot reasonably pin." The draft command uses v2. v1 stays for the record.

### 5. Pin and pre-registration

- `run.yml` `TRUSTBUT_SPEC: '0.7.0'`; README "running trustbut 0.7.0".
- `PREREGISTRATION.md`: trustbut 0.7.0 exactly; families text (proof gap and untested change come from `change-not-proven` as above; the 0.6.0 ids for older receipts); Thresholds section as in 3; prompt v2; and a new section **"Changes after the pilot"** listing these changes, the pilot numbers that led to them (precision 7%, accuracy 87%, 9 false from three causes), and that they were made after seeing pilot data, before `prereg-v1`.

## Testing

- `families`: `change-not-proven` with proofs → proof-gap; without → untested-change; 0.6.0 ids unchanged.
- `aggregate`: a folder mixing 0.6.0 and 0.7.0 receipts throws; a 0.7.0-only folder doesn't.
- `verdict`: pass depends only on accuracy and coverage; precision/hit rate carry `target: null`; the not-proven precision is computed from `finding.id`.
- `report`: tiles and the not-proven line render; existing report tests updated.
- `draft`: uses prompt v2.
